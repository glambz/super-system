# Retrospective and End-of-run report

## Retrospective

Every run, after final audit and before the report, write `retro.md` in the run folder: rounds per task, review failure reasons grouped by root cause, cap hits, scope violations, silently removed checks, blockers/stalls, runner/tool failures, quota events, wall-clock per phase. Derive concrete skill-improvement proposals (file, change, evidence from this run, expected effect). Append durable lessons to `~/.super-system/lessons.md` (one line each: date, lesson, evidence pointer; no duplicates).

## End-of-run report

What was produced (files, links); what was verified and how; what was not done or not verified; per task, review rounds and each role's platform/model; deficiencies accepted by the user; blocker and stall events and what the user chose; the run folder; the status line; the retro summary and the skill-improvement proposals (ask which to apply; never edit the skill without the user's approval); and, if overrides were used, the one question about saving them.
