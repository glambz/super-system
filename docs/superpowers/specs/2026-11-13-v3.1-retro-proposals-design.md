# super-system v3.1: the 13 retrospective proposals

Source: the four retrospectives of 2026-11-11..13 (`~/.super-system/runs/*/retro.md`) and `~/.super-system/lessons.md`. All 13 proposals approved by the user. Two tasks: **D** (documentation, items 1–5 and 7–13) and **S** (scripts, item 6). Their file sets don't overlap.

## Hard constraints (both tasks)

- `skills/super-system/SKILL.md` must stay ≤ 8192 bytes (`tests/check_skill.py` enforces it; it is ~8060 now). Never reword or compress existing rules to make room. Put new detail in reference files; if SKILL.md needs a pointer and there is no room, move an existing block out **verbatim** into a reference file and leave a one-line pointer (precedent: `docs/superpowers/specs/2026-11-09-external-runners-design.md` ~213).
- Each rule is stated once (check_skill checks it); no broken references; model names only in `references/platforms.md`; no personal paths or IDs in skill files.
- Never write an instruction telling an agent to load or run this skill itself.
- Keep every existing rule unless an item below changes it. House style: short sentences, plain words.

## Task D — documentation

1. **Fix-round size.** A fix round carries at most 3 Critical/Important findings. When more are open, the orchestrator asks the user: split across rounds (they count toward the round cap) or re-plan the task (it is probably too big). Minors never go into a fix round on their own (item 2). Where: the loops/rounds rules (SKILL.md "Loops" gets at most a pointer; detail in `references/runners.md` or `modes.md`, one place).
2. **Minor triage.** When a review passes with minors, the orchestrator decides once per task: accept (recorded as accepted minors) or schedule them for one **polish round** at the end of the run (all tasks' chosen minors, grouped by file ownership, reviewed like any round). Never open a new round per minor after a pass.
3. **Hard constraints block in every brief** (`references/runners.md` "Briefs"): known-failing tests that must stay failing (the orchestrator lists them by running the suite once on the base before Gate 2), shared files/helpers the task must not change, repo-enforced budgets/checks and the approved way to meet them, the interpreter/toolchain path.
4. **Base-diff guard** (`references/runners.md` "Is it done?"): before dispatching the reviewer, the orchestrator runs `scripts/removed-checks.py <worktree> <base> <files…>` (task S) and passes its list of removed permission/visibility/validation/error lines to the reviewer, who must confirm each is safe or reject.
5. **Decision log** (flows build/change/fix + `references/runners.md` "Briefs"): the plan file has a `## Decisions during the run` section; every orchestrator decision made after Gate 2 is appended there (date, decision, reason); briefs point to it; reviewers judge against it.
7. **Review flow verifier** (`references/flows/review.md`): after each area's scout, a fresh verifier (scout role) re-reads every cited line, reproduces cheaply where possible, applies the severity rubric, and marks duplicates; the orchestrator samples (all criticals + at least 1 in 5 of the rest) instead of re-reading everything. New `references/severity.md`: critical = exploitable without auth, across tenants/organisations, account takeover, or money figures wrong; important = real bug or weakness with a narrower blast radius; minor = correctness nits, dead code, performance, observability, missing tests; latent issues (unreachable today) at most important. A findings register template (ID, severity, location, summary, evidence, duplicates of) in review.md.
8. **Quota-aware scheduling** (`references/runners.md` "Run scripts"): before launching N runs on a runner, estimate N × typical run length against the runner's concurrency and its provider window (optional `cli.window_hours` in config); if it won't fit, tell the user and propose staggering or deferring.
9. **Worktree recipe** (`references/runners.md`, new section "Parallel tasks in worktrees"): one worktree per concurrent task from the base branch; copy the git-ignored env files the tests need; link dependency folders instead of copying (e.g. `node_modules` junction on Windows); absolute worktree paths in every brief (agents' working directories drift); merge order and conflict handling; cleanup with `scripts/worktree-cleanup.sh` (task S): unlink dependency links first, then remove worktrees (they hold secret copies).
10. **Pre-deploy data checks** (`references/track-backend.md` "Verify"): when a change adds migrations or changes data rules, write read-only SQL checks from the plan (rows affected, values that change meaning, test data) and run them against the dev/test database before merging; report the results; never write.
11. **Numeric rules** (`references/track-backend.md` + `references/roles/reviewer.md`): when a task implements money/numeric rules, the plan includes worked examples and the reviewer computes them through the real functions with a script.
12. **Documentation changes** (`references/roles/reviewer.md` + `references/flows/change.md`): for changes to docs or instruction files, the reviewer lists every changed pre-existing sentence; any change the spec didn't require is a finding.
13. **Accepted minors carried forward** (`references/retrospective.md` + startup in SKILL.md or flows): the retro lists accepted minors; at the next run for the same project, the orchestrator reads the previous run's `retro.md` and shows its accepted minors at Gate 1/2 as candidates.
- Extend `tests/check_skill.py` for the new pieces (severity.md exists and is referenced; runners.md has the worktree and quota sections and the hard-constraints brief item; review.md has the verifier step; retrospective.md mentions accepted minors; decision log in the flows). Update `README.md` "What's new" with a short v3.1 list.
- Files allowed: `skills/super-system/SKILL.md`, `skills/super-system/references/**` (not `scripts/`), `README.md`, `tests/check_skill.py`.

## Task S — scripts (item 6)

Tested helper scripts under `skills/super-system/scripts/` (bash for Git Bash on Windows and POSIX shells, Python 3 stdlib only), so the orchestrator stops writing them ad hoc. Each script starts with a usage comment; no personal paths or model names (they take paths/models as arguments or from `~/.super-system/config.json`).

| Script | Does |
|---|---|
| `run-agy.sh` | One Antigravity run: args task name, worktree, run folder, round, schema file, model, effort, optional conversation id. Closes stdin, writes `.jsonl`/`.err`, extracts `structured_output` to `results/<name>.json`, writes `<name>.meta` (exit, status, conversation id). |
| `run-codex.sh` | One Codex run (fresh or resume): args task name, project folder, run folder, round, schema file, model, effort, optional thread id. Closes stdin; result to `-o`; retries on 429 (300 s, ≤ 3); succeeds only when the result parses as JSON and has the role's required key (`verdict` for reviewers, `status` for implementers, `findings` for scouts). |
| `review-wrap.sh` | Hashes the task's changed files (vs base, plus untracked) before and after a reviewer run and reports whether the reviewer changed anything. |
| `queue.sh` | Runs a list of commands with a concurrency cap (arg), staggered starts. |
| `wait-done.sh` | Waits until a file contains a pattern or a log has been idle for N minutes (simple loop; prints "done"/"stalled"). |
| `removed-checks.py` | Args worktree, base, files…: lists removed lines from `git diff <base> -- <files>` that look like permission/visibility/validation/error checks (patterns such as `raise`, `HTTPException`, `require_`, `check_`, `assert`, `deny`, `forbidden`, `401`, `403`, `404`, `permission`, `visible`, `scope`, `if not`). Sets `MSYS_NO_PATHCONV=1` for git calls. |
| `worktree-setup.sh` | Args repo, worktree path, branch, base, env files…, link dirs…: creates the worktree, copies the env files, links the dependency folders (directory junction on Windows via `cmd //c mklink /J`, symlink elsewhere). |
| `worktree-cleanup.sh` | Args repo, worktree paths…: removes dependency links first without following them (`cmd //c rmdir` on Windows, `rm` of the link elsewhere), then `git worktree remove --force` and `git worktree prune`. |

- Rule baked into the scripts' header and runners.md (Task D references it): copy the scripts into the run folder at the start of a run and run the copies; never edit a script while it runs.
- New `tests/check_scripts.py` (stdlib): every script exists, has a usage comment, passes `bash -n` (shell) or `py_compile` (Python), contains no personal paths and no model names; and a small functional test of `removed-checks.py` on a temporary git repo (a removed `raise HTTPException` line is reported, an unrelated removed line is not).
- Files allowed: `skills/super-system/scripts/*` (new files; leave `contrast-check.py` unchanged), `tests/check_scripts.py`.
